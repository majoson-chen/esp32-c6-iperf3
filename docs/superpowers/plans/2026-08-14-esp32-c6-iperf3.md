# ESP32-C6 iperf3 Implementation Plan

> **For agentic workers:** 本计划使用 **Shallow Plan Mode**。地图不是施工手册。执行者先读仓库和 `docs/design.md`，再动手；边做边用主机单测 / 交叉编译 / 板上 `iperf3` 验证。

**Goal:** 落地 `docs/design.md`：可主机测试的 iperf3 server 子集 + C6 STA 固件 + 开源仓库与硬件验收报告。

**Architecture:** `iperf3-proto`（no_std 状态机）与 `firmware`（esp-radio STA + embassy-net）分层。协议不依赖芯片。

**Tech Stack:** Rust 2024 edition；crates.io 上已发布的 `esp-hal` / `esp-radio` / `esp-rtos` / `embassy-net` 组合；桌面 `iperf3` 3.21 做硬件对端。

## Global Constraints

- 合同与红线以 [`docs/design.md`](../design.md) 为 SSOT，冲突时改代码不改口。
- 凭证只来自环境变量 `SSID` / `PASSWORD`，永不入库。
- 目标三元组：`riscv32imac-unknown-none-elf`。
- 许可证 MIT OR Apache-2.0；公开仓库 `majoson-chen/esp32-c6-iperf3`。
- 协议行为对齐 esnet/iperf **3.21** 源码（控制状态机 + UDP datagram），不以 2014 wiki 为最终依据。
- 实现用 crates.io 发布版，不跟 `esp-hal` `main`。
- 控制器（本会话）执行阶段按 Shallow Plan：产品代码交给子代理；子代理模型 `cursor-grok-4.6-high`。

---

## 1. What we are building

一块上电即用的 ESP32-C6 固件：STA 加入 2.4 GHz WPA2 AP，DHCP 后在 TCP 5201 跑 iperf3 **server 子集**。桌面 `iperf3 -c` / `-u` / `-R` 能跑完出数。协议状态机做成独立 crate，在 macOS host 上单测；GitHub Actions 只跑这些单测和 C6 交叉编译。硬件实测在开发机完成，报告写入 `docs/hardware-test.md`（SSID 打码）。

仓库是 Cargo workspace，开源门面（LICENSE、双语 README、CI、gitignore）与固件一起交，而不是事后补。

## 2. Acceptance criteria

- `cargo test -p iperf3-proto` 在 host 全绿。
- `SSID`/`PASSWORD` 可为占位符时，`cargo build --release --target riscv32imac-unknown-none-elf` 成功。
- 真板 + 2.4 GHz WPA2：设计 §1 四条合同命令各至少一次成功；daemon 连续两次；`-P 2` 拒绝后仍能再跑 `-c`。
- 串口出现 `IP4=`；git 中无密码、无未打码 SSID。
- `origin` 指向公开 repo `majoson-chen/esp32-c6-iperf3`，`main` 上有 LICENSE 与 README。

## 3. Red lines / deliberate non-goals

- 不实现 client、AP、APSTA、多流、bidir、IPv6、SCTP、鉴权。
- 不把 Wi‑Fi 密码或完整 SSID 写入将推送的文件。
- 不把「达到 IDF 官方 Mbps」写成通过条件。
- 不在计划里锁死 `esp-radio` 的具体函数名（1.0 example 与更新 API 不同）；执行者按所选 crates.io 版本的官方 STA+DHCP example 写 bring-up。
- 不在 GitHub Actions 里接真板。

## 4. Work packages and rough dependencies

```
WP0 仓库骨架
  └─ WP1 iperf3-proto（TDD，host）
        └─ WP2 firmware STA + 把 socket 接到状态机
              └─ WP3 工具链、烧录、硬件合同命令、hardware-test.md
                    └─ WP4 README/CI/LICENSE 收口并 push GitHub
```

WP0 可与 WP1 部分并行，但 WP2 必须能 `use iperf3_proto`。WP4 的 CI yaml 可在 WP1 通了之后就写，push 放最后。

### WP0 — 开源骨架

gitignore（含 `.env`、`target/`）、workspace `Cargo.toml`、`LICENSE-MIT` / `LICENSE-APACHE`、`.env.example`（假 SSID/PASSWORD）、`rust-toolchain.toml`（含 riscv 目标）。不写业务逻辑。

### WP1 — `iperf3-proto`

TDD：先红后绿。覆盖 cookie 长度、参数 JSON 的接受/拒绝、状态字节顺序、结果 JSON 能被 serde 读出约定字段、UDP 头编解码（对照 3.21）。对外接口保持小：输入字节 → 输出「写这些字节 / 接受数据连接 / 泵 / 结束」。具体类型名由执行者定，但后续 WP 只能依赖本包 public API。

### WP2 — firmware

按所选版本官方 `embassy_dhcp`（或同等 STA+DHCP）把 Wi‑Fi 拉起来：省电关、最高 CPU、DHCP、`IP4=`、断线重试。listen 5201；控制连接与一条数据流接到 WP1。TCP 与 UDP、正向与 reverse 都要接到状态机，而不是先做一个「只能 TCP」的临时协议。

### WP3 — 板上验收

安装本机缺的 `espflash` 与 riscv target。释放占用 `/dev/cu.usbmodem*` 的 Thonny。用本地环境变量编译烧录（变量不写进仓库文件）。跑设计 §1 命令，把输出摘要写入 `docs/hardware-test.md`。失败则修 WP1/WP2，不改合同装过关。

### WP4 — 发布

双语 README（构建、烧录、合同、限制）。GitHub Actions：host test + C6 build（dummy 凭证）。`gh repo create majoson-chen/esp32-c6-iperf3 --public` 并 push。已登录账号 `majoson-chen`。

## 7. Anchors

- 控制端口 **5201**；cookie **37** 字节。
- 状态字节：`PARAM_EXCHANGE=9`，`CREATE_STREAMS=10`，`TEST_START=1`，`TEST_RUNNING=2`，`TEST_END=4`，`EXCHANGE_RESULTS=13`，`DISPLAY_RESULTS=14`，`IPERF_DONE=16`，`ACCESS_DENIED=-1`，`SERVER_ERROR=-2`。
- C6：2.4 GHz only，无 WPA3；测试必须用 2.4 GHz WPA2 AP。
- 开发机：iperf 3.21；以太网与 5 GHz 已在 `192.168.31.0/24`；C6 进同一网段即可。
- 烧录会覆盖 MicroPython；USB 口可能被 Thonny 独占。
- 开源风格对齐 `stm32f103-serial-rs`：双许可、中英 README、Cargo 元数据。
